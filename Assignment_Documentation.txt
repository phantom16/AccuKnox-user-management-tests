================================================================================

This project is a QA assignment that demonstrates end-to-end testing of the
User Management module in OrangeHRM, an open-source HR management system.

3. STEP-BY-STEP SETUP GUIDE (FROM SCRATCH)
================================================================================

This guide assumes you have NOTHING installed except Windows.

--- STEP A: Install Python ---

  1. Go to https://www.python.org/downloads/
  2. Download Python 3.10 or newer (3.12+ recommended)
  3. Run the installer
     IMPORTANT: Check the box "Add Python to PATH" at the bottom!
  4. Click "Install Now"
  5. Open Command Prompt (press Win+R, type "cmd", press Enter)
  6. Verify:

     python --version
     # Should show: Python 3.12.x or similar

--- STEP B: Install Git ---

  1. Go to https://git-scm.com/downloads
  2. Download and install Git for Windows (use all default options)
  3. Verify:

     git --version
     # Should show: git version 2.x.x

--- STEP C: Clone the Repository ---

  1. Open Command Prompt or Git Bash
  2. Navigate to where you want the project:

     cd Desktop

  3. Clone the repository:

     git clone https://github.com/phantom16/AccuKnox-user-management-tests.git

  4. Enter the project folder:

     cd AccuKnox-user-management-tests

--- STEP D: Create a Virtual Environment (Recommended) ---

  A virtual environment keeps project dependencies isolated from system Python.

  1. Create it:

     python -m venv venv

  2. Activate it:

     # On Windows Command Prompt:
     venv\Scripts\activate

     # On Git Bash:
     source venv/Scripts/activate

     # You should see (venv) at the start of your prompt

--- STEP E: Install Dependencies ---

  1. Install all Python packages:

     pip install -r requirements.txt

  2. Install Playwright's Chromium browser:

     playwright install chromium

     This downloads a Chromium browser that Playwright will control.

--- STEP F: Run the Tests! ---

  1. Run all 10 tests:

     pytest

  2. A browser window will open and you'll see it perform actions automatically
  3. Final output should show: "10 passed"

THAT'S IT! You now have the entire project running.

5. PROBLEM STATEMENT 1: AUTOMATION CODE EXPLAINED
================================================================================

The automation uses Playwright (Python) with the Page Object Model (POM).

What is Page Object Model?
  - Each web page gets its own Python class
  - The class contains selectors (how to find elements) and actions (what to do)
  - Tests call page methods instead of dealing with selectors directly
  - If the UI changes, you only fix the page class, not every test


--------------------------------------------------------------------------------
5.1  login_page.py  (pages/login_page.py)
--------------------------------------------------------------------------------

PURPOSE: Handles the OrangeHRM login page

CODE WALKTHROUGH:

  class LoginPage:
      URL = "https://opensource-demo.orangehrmlive.com/web/index.php/auth/login"

      def __init__(self, page):
          self.page = page
          self.username_input = page.locator("input[name='username']")
          self.password_input = page.locator("input[name='password']")
          self.login_button = page.locator("button[type='submit']")

EXPLANATION:
  - __init__ receives the Playwright "page" object (the browser tab)
  - It stores 3 locators: username field, password field, login button
  - Locators use CSS selectors to find elements on the page

  Methods:

  navigate()
    - Calls page.goto(URL) to open the login page in the browser
    - wait_for_load_state("networkidle") waits until no network requests
      are pending, ensuring the page fully loaded

  login(username, password)
    - .fill() types text into the input fields
    - .click() clicks the login button
    - Waits for network to settle after login

  verify_dashboard_visible()
    - Uses expect() to assert the "Dashboard" heading is visible
    - timeout=15000 means it waits up to 15 seconds
    - If Dashboard doesn't appear, the test fails here

5.2  admin_page.py  (pages/admin_page.py)
--------------------------------------------------------------------------------

PURPOSE: Handles ALL User Management actions (search, add, edit, delete)
         This is the biggest and most important file.

KEY DESIGN DECISION - LABEL-BASED SELECTORS:

  def _get_field_group(self, label_text):
      return self.page.locator(
          f".oxd-form .oxd-grid-item:has(.oxd-label:text-is('{label_text}'))"
      )

  WHY? OrangeHRM uses nested CSS grids. Selectors like "nth-child(3)" break
  when the form layout changes. Instead, we find fields by their visible
  label text (e.g., "Username", "Status"). This is:
    - More reliable (labels don't change)
    - Self-documenting (you can read what field it targets)
    - Works on both the Add form and Search form

  Helper methods built on this:

  _select_dropdown(label_text, option_text)
    - Finds the dropdown by its label, clicks it to open
    - Then clicks the matching option in the dropdown list

  _fill_input(label_text, value)
    - Finds the text input by its label
    - Fills it with the given value

ALL METHODS EXPLAINED:

  Navigation:
    navigate_to_admin()         - Clicks "Admin" in sidebar, waits for page
    verify_admin_page_loaded()  - Checks "System Users" heading is visible

  Search:
    search_by_username(name)    - Fills Username field, clicks Search
    search_by_role(role)        - Selects role dropdown, clicks Search

  Table:
    get_table_rows()            - Returns all rows in the results table
    get_first_row_cells()       - Returns cells of the first row
    get_record_count()          - Returns number of rows

  Add User:
    click_add()                 - Clicks "+ Add" button, waits for form
    select_user_role(role)      - Picks role from dropdown (Admin/ESS)
    select_status(status)       - Picks status (Enabled/Disabled)
    fill_employee_name(name)    - Types partial name, waits for autocomplete,
                                  clicks first suggestion
    fill_username(name)         - Types into Username field
    fill_password(pwd)          - Fills both Password and Confirm Password
    click_save()                - Clicks Save, waits for response

  Verification:
    verify_success_toast(msg)   - Waits for green toast notification to appear
                                  and checks it contains the expected message

  Edit User:
    click_first_row_edit()      - Clicks the pencil icon on the first row
    toggle_change_password()    - Clicks "Yes" label to show password fields

  Delete User:
    click_first_row_delete()    - Clicks the trash icon on the first row
    confirm_delete()            - Clicks "Yes, Delete" in the popup dialog
    verify_no_records_found()   - Checks "No Records Found" span is visible

5.3  conftest.py  (tests/conftest.py)
--------------------------------------------------------------------------------

PURPOSE: Pytest fixtures - reusable setup code that runs before each test

WHAT ARE FIXTURES?
  Fixtures are functions decorated with @pytest.fixture. When a test method
  has a parameter with the same name as a fixture, pytest automatically
  runs the fixture first and passes the result to the test.

CODE WALKTHROUGH:

  @pytest.fixture(scope="session")
  def browser_context_args():
      return {"viewport": {"width": 1280, "height": 720},
              "ignore_https_errors": True}

  -> Sets browser window to 1280x720 for all tests in the session
  -> ignore_https_errors prevents SSL certificate failures

  @pytest.fixture()
  def logged_in_page(page):
      login = LoginPage(page)
      login.navigate()
      login.login("Admin", "admin123")
      login.verify_dashboard_visible()
      return page

  -> "page" is a built-in Playwright fixture (a fresh browser tab)
  -> This fixture logs in before the test and returns the page at Dashboard
  -> Each test gets a FRESH browser session

  @pytest.fixture()
  def admin_page(logged_in_page):
      admin = AdminPage(logged_in_page)
      admin.navigate_to_admin()
      return admin

  -> Depends on logged_in_page (pytest runs that first)
  -> Navigates to Admin module, returns AdminPage object
  -> When a test asks for "admin_page", it gets: login -> admin nav -> ready

HOW THE CHAIN WORKS:
  Test requests "admin_page"
    -> pytest sees admin_page needs logged_in_page
    -> pytest sees logged_in_page needs page (built-in)
    -> Playwright opens browser, creates page
    -> logged_in_page logs in
    -> admin_page navigates to Admin
    -> Test receives ready-to-use AdminPage object

6. HOW TO RUN THE TESTS
================================================================================

--- Run All Tests (Default) ---

  pytest

  This runs all 10 tests with a visible browser (headed mode) and
  300ms slow motion between actions (configured in pytest.ini).

--- Run in Headless Mode (No Browser Window) ---

  pytest --headless

--- Run a Specific Test ---

  # Only the Add User test:
  pytest tests/test_user_management.py::TestAddUser -v

  # Only the Delete test:
  pytest tests/test_user_management.py::TestDeleteUser -v

  # Only the Search tests:
  pytest tests/test_user_management.py::TestSearchUser -v

--- Run with HTML Report ---

  pip install pytest-html
  pytest --html=report.html --self-contained-html

  Then open report.html in your browser for a visual test report.

--- Configuration File (pytest.ini) ---

  [pytest]
  testpaths = tests
  addopts = --headed --slowmo=300 -v

  - testpaths = tests    -> Look for tests in the "tests/" folder
  - --headed             -> Open a visible browser window
  - --slowmo=300         -> 300ms delay between Playwright actions
  - -v                   -> Verbose output (shows each test name)

7.1  system_health_monitor.py  (scripts/system_health_monitor.py)
--------------------------------------------------------------------------------

PURPOSE: Monitors CPU, memory, disk space, and running processes.
         Alerts when any metric exceeds predefined thresholds.

LIBRARY USED: psutil (cross-platform system monitoring)

THRESHOLDS (configurable at the top of the file):
  CPU_THRESHOLD    = 80%
  MEMORY_THRESHOLD = 80%
  DISK_THRESHOLD   = 80%
  TOP_PROCESSES    = 5

HOW EACH FUNCTION WORKS:

  check_cpu()
    - psutil.cpu_percent(interval=1) samples CPU for 1 second
    - If usage > 80%, logs a WARNING alert
    - Returns the percentage value

  check_memory()
    - psutil.virtual_memory() returns memory stats
    - .percent = usage percentage
    - .total = total RAM in bytes (converted to GB for display)
    - .available = free RAM
    - Alerts if > 80%

  check_disk()
    - psutil.disk_partitions() lists all drives (C:\, D:\, etc.)
    - For each drive, psutil.disk_usage() gets usage stats
    - Alerts for each drive that exceeds 80%
    - Handles PermissionError for restricted drives

  check_processes()
    - Iterates all running processes via psutil.process_iter()
    - Collects PID, name, CPU%, memory% for each
    - Sorts by CPU usage descending
    - Displays the top 5

  generate_report()
    - Runs all 4 checks
    - Prints overall status: "HEALTHY" or "ALERTS DETECTED"

HOW TO RUN:

  python scripts/system_health_monitor.py

  Output goes to both the console AND scripts/system_health.log

7.2  app_health_checker.py  (scripts/app_health_checker.py)
--------------------------------------------------------------------------------

PURPOSE: Checks if web applications are up or down by making HTTP requests
         and evaluating response status codes.

LIBRARY USED: requests (HTTP library)

DEFAULT URLS CHECKED:
  1. OrangeHRM login page          -> should be UP (200)
  2. Google.com                    -> should be UP (200)
  3. httpstat.us/500               -> always returns 500 (tests DOWN detection)
  4. nonexistent domain            -> tests connection error handling

HOW IT WORKS:

  check_url(url)
    - Makes an HTTP GET request with 10-second timeout
    - If status code 200-399: status = "up" (healthy)
    - If status code 400+: status = "down" (problem)
    - Catches ConnectionError: DNS failure, server unreachable
    - Catches Timeout: server took too long to respond
    - Returns a dict with: url, status_code, response_time_ms, status, error

  check_all(urls)
    - Loops through all URLs
    - Calls check_url() for each
    - Logs results as they come in

  print_report(results)
    - Prints a formatted table: URL | Status | Code | Time
    - Shows totals: how many up vs down

HOW TO RUN:

  # Check default URLs:
  python scripts/app_health_checker.py

  # Check your own URLs:
  python scripts/app_health_checker.py https://example.com https://myapp.com

  Output goes to both the console AND scripts/app_health.log
